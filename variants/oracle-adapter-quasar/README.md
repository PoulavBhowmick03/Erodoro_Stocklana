# oracle-adapter, Quasar variant — blocked on two v0.1.0 gaps

Status as of 2026-08-15: **does not compile.** The port is written and faithful;
two capabilities it needs are missing from Quasar v0.1.0. Both were verified
against the framework source at `github.com/blueshift-gg/quasar`, not inferred
from docs.

Keeping the code rather than deleting it: neither gap is architectural, both are
the kind of thing a beta closes, and when they do this compiles as written.

## Why this variant was attempted

Quasar sits exactly where this codebase would want a framework to sit. Anchor
derives the account checks and pays ~200 KB for it. Pinocchio deletes the
framework and hands the checks back to you — and those checks *are* the security
model, so hand-maintaining them is the real cost, not the typing. Quasar keeps
`#[derive(Accounts)]`, `init`, `has_one` and PDA seeds declarative while casting
accounts straight out of the input buffer.

If it worked, it would be the interesting answer. That is why it is worth
recording precisely what stopped it.

## Blocker 1: no access to the raw bytes of a foreign-owned account

An oracle adapter's whole job is to decode an account owned by *someone else* —
here a `PriceUpdateV2` owned by the Pyth receiver. That needs two things from
the framework: the account's owner, and its bytes.

Quasar's account wrappers are generated by `define_account!` as
`#[repr(transparent)]` structs holding a private `view: AccountView`
(`lang/src/macros.rs`). What the wrapper exposes:

- `Deref`/`DerefMut` to the *typed* zero-copy view of the account's data
- `address()`
- `from_account_view_unchecked` — the inbound direction only

What it does not expose: any accessor returning `&AccountView`, an
`AsRef<AccountView>` impl, `owner()`, or `try_borrow()`. Searched the whole
repository: no example or test program anywhere reads raw bytes from an
`UncheckedAccount`.

The typed `Deref` is not a substitute. It reinterprets the account as *our*
schema, and a Pyth account is not our schema — that is the entire problem.

The only escape is transmuting through the `#[repr(transparent)]` guarantee.
That is probably sound, and it is the wrong thing to put in an oracle read path
in a beta framework, so it is not done here.

## Blocker 2: `i64` instruction arguments do not compile

```
error[E0277]: the trait bound `PodI64: SchemaWrite<Configuration<...>>` is not satisfied
   --> src/lib.rs:76:23
```

`max_age_secs: i64` is part of the Anchor ABI this variant has to match. The
derive maps `i64` to `PodI64`, which has no `SchemaWrite` implementation.

Confirming it is a gap rather than a mistake here: across every example and test
program in the Quasar repository, the instruction-argument types actually used
are `u64`, `u32`, `u8`, `bool`, `String` and `Address`. **No signed integer
argument appears anywhere.**

Changing the field to `u64` would compile and would silently break ABI
compatibility with the Anchor build, so it is not done here either.

## What did work

Worth recording, because it is most of the port:

- `#[account(discriminator = [...], set_inner)]` accepts a full 8-byte
  discriminator, so the account is byte-compatible with Anchor's
  `sha256("account:FeedConfig")[..8]`. Multi-byte discriminators are supported
  even though the examples all use compact single-byte tags.
- `#[instruction(discriminator = [...])]` likewise takes 8 bytes, so the
  instruction ABI matches too.
- `#[instruction(feed_id: [u8; 32])]` on the `Accounts` struct feeds an
  instruction argument into a PDA seed — the `Anchor` pattern this program needs
  for `FeedConfig::seeds(feed_id)`.
- `has_one(admin)` (parenthesised, not `has_one = admin`).
- `init`, `payer`, `Signer`, `Program<SystemProgram>` all behave as expected.

## Re-check when

Quasar cuts a release past v0.1.0. Specifically: an `AsRef<AccountView>` or
equivalent accessor on account wrappers, and `SchemaWrite` for the signed `Pod`
types. Neither needs a redesign.

Until then the three-way comparison in `variants/COMPARISON.md` runs on Anchor
and Pinocchio, with this recorded as a measured absence rather than an omission.
